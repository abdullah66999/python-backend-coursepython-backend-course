1.1. Что нужно установить

Установите актуальный Python 3 с официального сайта python.org и редактор VS Code. При установке Windows включите Add Python to PATH. Проверка в терминале:

1.2. Инструкции и отступы

Python выполняет инструкции сверху вниз. Блоки кода обозначаются отступами в четыре пробела, а не фигурными скобками.

name = "Анна"
print("Привет,", name)

if len(name) > 3:
    print("Имя длиннее трёх символов")
Правило
Одна строка — одна понятная мысль. Не бойтесь делать промежуточные переменные: они облегчают отладку.

1.3. Как читать ошибку

В traceback смотрите на последнюю строку: там обычно указан тип ошибки и причина. Номер строки в стеке помогает найти место, но исправлять нужно не всегда именно последнюю строку.

2.1. Типы

Основные типы: int — целое число, float — дробное, str — текст, bool — истина или ложь, None — отсутствие значения.

count = 7
price = 19.90
title = "Книга"
is_available = True
nothing = None

print(type(price))

В Python переменная — это имя, связанное со значением. Тип принадлежит значению, поэтому одна и та же переменная может получить другое значение, но смешивать типы без явного преобразования нельзя.

2.2. Строки и форматирование

Для строк используйте одинарные или двойные кавычки. f-строки удобны, когда в текст нужно вставить значения:

user = "Ирина"
score = 87
message = f"{user} набрала {score} баллов"
print(message)

text = "python"
print(text.upper(), text[0], text[1:4], len(text))

Индексы начинаются с нуля. Срез text[start:stop] не включает правую границу.

2.3. Операторы и ввод

Арифметика: +, -, *, /, //, %, **. Сравнения возвращают True или False. Функция input() всегда возвращает строку.

print(f"Вам примерно {age} лет")

Урок 3. Ветвления и циклы · 60–120 минут
Примерное время: 90–120 минут

Цель урока: выражать правила и повторять действия

3.1. if / elif / else

Условие проверяется сверху вниз. Выполнится только первый подходящий блок.

temperature = 18
if temperature < 0:
    status = "мороз"
elif temperature < 15:
    status = "прохладно"
else:
    status = "тепло"
print(status)

Для составных условий используются and, or, not. Для сравнения значений — ==, а одиночный = означает присваивание.

3.2. for и while

for перебирает элементы последовательности. range(5) даёт числа от 0 до 4. while повторяет блок, пока условие истинно.

total = 0
for number in range(1, 6):
    total += number
print(total)  # 15

attempts = 0
while attempts < 3:
    print("Попытка", attempts + 1)
    attempts += 1
Осторожно
В цикле while обязательно изменяйте состояние, влияющее на условие. Иначе получится бесконечный цикл.

3.3. break и continue

break завершает цикл, а continue пропускает текущую итерацию. Используйте их умеренно: понятный цикл обычно лучше сложного.

numbers = [3, -1, 8, 0, 10]
for number in numbers:
    if number < 0:
        continue
    if number == 0:
        break
    print(number)

Урок 4. Коллекции · 60–120 минут
Примерное время: 120 минут

Цель урока: хранить и обрабатывать наборы значений

4.1. Список и кортеж

Список изменяем: в него можно добавлять и удалять элементы. Кортеж похож на список, но обычно используется для фиксированной структуры.

tasks = ["прочитать", "потренироваться"]
tasks.append("отдохнуть")
for index, task in enumerate(tasks, start=1):
    print(index, task)

point = (10, 20)
x, y = point

Полезные операции списка: append, remove, pop, sort, len. Не меняйте список во время перебора без чёткого понимания последствий.

4.2. Словарь

Словарь хранит пары «ключ → значение». Это естественный тип для описания объекта, например профиля пользователя.

user = {"name": "Лена", "age": 24, "skills": ["python", "git"]}
print(user["name"])
user["city"] = "Казань"
for key, value in user.items():
    print(key, value)

Метод get позволяет безопасно получить необязательный ключ: user.get('email', 'не указан').

4.3. Множества и включения

Множество set хранит уникальные элементы. Включения (comprehensions) помогают коротко построить коллекцию, но не должны превращаться в ребус.

tags = ["python", "web", "python", "data"]
unique_tags = set(tags)
even = [n for n in range(10) if n % 2 == 0]
lengths = {tag: len(tag) for tag in unique_tags}
print(unique_tags, even, lengths)

Переменная — это имя значения · 60 минут

Переменная — это имя, по которому программа может обратиться к значению. Оператор = не означает «равно» в математике: он связывает имя и значение.

Числа и операции · 75 минут

minutes = 135

print(round(10 / 3, 2))

if проверяет первое правило, elif — следующие, else — запасной вариант. Отступ в четыре пробела показывает тело блока.

score = int(input("Баллы: "))
if score < 0 or score > 100:
    result = "Некорректный балл"
elif score >= 90:
    result = "Отлично"
elif score >= 60:

11.1. Класс

Класс описывает общую форму и поведение объектов. self — ссылка на конкретный экземпляр.

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Сумма должна быть положительной")
        self.balance += amount

account = BankAccount("Ольга")
account.deposit(500)
print(account.owner, account.balance)

Методы меняют состояние или возвращают результат. Не делайте класс только ради того, чтобы заменить три строки словаря.

11.2. dataclass

Для объектов-данных используйте dataclass: он создаёт конструктор, сравнение и удобное представление.

from dataclasses import dataclass

@dataclass
class Task:
    title: str
    done: bool = False

task = Task("Выучить функции")
task.done = True
print(task)

Аннотации типов помогают читателю и редактору, но сами по себе не проверяют значения во время выполнения.

11.3. Композиция лучше наследования

Наследование связывает классы жёстко. Композиция («объект содержит другой объект») обычно гибче. Наследуйтесь, когда отношение «является» действительно естественно: Admin является User.

17.1. Сложность

Оценка Big O показывает, как растёт работа при увеличении входа. Один проход по списку — O(n), два вложенных прохода — часто O(n²), поиск ключа в словаре — в среднем O(1).

def has_duplicate(items):
    seen = set()
    for item in items:
        if item in seen:
            return True
        seen.add(item)
    return False

Backend принимает запрос, проверяет его, выполняет бизнес-правила, обращается к данным и возвращает ответ. Это не магия фреймворка, а последовательность границ, у каждой из которых есть ответственность.

REST, статусы и контракты · 100 минут

REST — это не набор обязательных URL, а стиль проектирования ресурсов. Хороший API последователен: одинаковые ошибки имеют одинаковую форму, пагинация предсказуема, а сервер не заставляет клиента угадывать.

Пример ресурса

POST   /tasks

Коды, которые нужно знать

  • 200 / 201 / 204 — успешное чтение, создание, ответ без тела.

  • 404 — ресурс не найден.

  • 422 — структура входа не прошла валидацию.
  • 429 / 500 — ограничение частоты или ошибка сервера.
Разбор. Если пользователь повторно создаёт заказ с тем же idempotency key, ответ 409 может быть точнее, чем 500.

Зависимости и DI · 130 минут

Dependency Injection передаёт обработчику готовые ресурсы: соединение с базой, текущего пользователя, настройки или клиент внешнего сервиса. Обработчик остаётся коротким, а зависимости можно заменить в тесте.

from collections.abc import Generator
from fastapi import Depends, FastAPI

app = FastAPI(title="Tasks API")

class TaskRepository:
    def list(self):
        return []

    def close(self):
        pass

def get_repository() -> Generator[TaskRepository, None, None]:
    repository = TaskRepository()
    try:
        yield repository
    finally:
        repository.close()

@app.get("/tasks")
def list_tasks(repo = Depends(get_repository)):
    return repo.list()

Что не класть в dependency

Не прячьте в зависимостях неожиданную бизнес-логику. Если функция проверяет права, назовите её как проверку прав. Явные зависимости проще читать и мокать.

class Base(DeclarativeBase):

Пароли, access и refresh token · 150 минут

Пароль нельзя шифровать обратимо и нельзя хранить как есть. Используйте медленный password hashing: Argon2id или bcrypt с актуальными параметрами.

Две короткие модели

Session cookie удобна для браузера: сервер хранит сессию, cookie имеет HttpOnly, Secure и SameSite. JWT удобен для stateless API, но его отзыв и хранение требуют дисциплины.

access token: короткоживущий, например 10 минут
refresh token: дольше, хранится осторожно, можно отозвать

Event loop и границы async · 120 минут

Event loop обслуживает множество задач, пока они ждут I/O. Он не делает CPU-код параллельным. Если обработчик выполняет тяжёлый JSON-парсинг или ML-вычисление, вынесите работу в процесс или worker.

FSM-анкета: построчный разбор · 180 минут

FSM хранит, на каком шаге диалога находится конкретный пользователь. Это лучше, чем глобальная переменная или десятки флагов.

from aiogram.fsm.context import FSMContext
from aiogram.fsm.state import State, StatesGroup

class ProfileForm(StatesGroup):
    name = State()
    city = State()

@router.message(Command("profile"))
async def profile_start(message: Message, state: FSMContext) -> None:
    await state.set_state(ProfileForm.name)
    await message.answer("Как тебя зовут?")

@router.message(ProfileForm.name)
async def profile_name(message: Message, state: FSMContext) -> None:
    await state.update_data(name=message.text.strip())
    await state.set_state(ProfileForm.city)
    await message.answer("В каком городе ты живёшь?")

@router.message(ProfileForm.city)
async def profile_finish(message: Message, state: FSMContext) -> None:
    data = await state.update_data(city=message.text.strip())
    await state.clear()
    await message.answer(f"Сохранено: {data['name']}, {data['city']}")
Что делает каждая строка
FSMContextДаёт доступ к данным и текущему состоянию диалога пользователя.
State, StatesGroupСоздают типизированный набор шагов формы.
class ProfileFormОбъявляем два шага: имя и город.
await state.set_state(...)Переводим пользователя в следующий шаг.
await state.update_data(name=...)Сохраняем ответ до завершения формы.
@router.message(ProfileForm.name)Следующий handler сработает только для пользователей на шаге name.
data = await state.update_data(...)Добавляем последний ответ и получаем все данные формы.
await state.clear()Очищаем состояние после успешного завершения сценария.

Проверка HMAC: построчный разбор · 150 минут

Подпись считается от исходных байтов тела. Нельзя сначала распарсить JSON и сериализовать его обратно: пробелы и порядок полей могут измениться.

import hashlib
import hmac

def verify_signature(body: bytes, header: str, secret: str) -> bool:
    expected = hmac.new(
        secret.encode(), body, hashlib.sha256
    ).hexdigest()
    received = header.removeprefix("sha256=")
    return hmac.compare_digest(expected, received)

def find_matches(root: Path, query: str) -> list[dict]:
    pattern = re.compile(query, re.IGNORECASE)

HTTP-запрос не должен ждать долгий экспорт. Он создаёт job, очередь передаёт job worker, а клиент читает статус.

queued -> running -> done
                  -> failed

POST /jobs       {"job_id": "...", "status": "queued"}
GET  /jobs/{id}  {"status": "running"}

Сразу определите, что происходит при исключении, повторе и остановке процесса. Очередь без политики отказа быстро становится источником потерянных задач.

Домашняя работа: Спроектировать очередьНарисуйте состояние job, владельца, число попыток и момент, когда задача считается окончательно неуспешной.
  • Есть status.
  • Есть retry policy.
  • Понятен shutdown.
  • Повтор не создаёт новую job.

Уровень выше: Добавьте приоритеты и dead-letter очередь.

Producer и worker: построчный разбор · 170 минут

asyncio.Queue даёт безопасный канал между producer и worker внутри одного процесса. Внешняя очередь понадобится при нескольких экземплярах сервиса.

import asyncio
from dataclasses import dataclass

@dataclass
class Job:
    id: int
    name: str
    attempts: int = 0

queue: asyncio.Queue[Job] = asyncio.Queue()

async def worker() -> None:
    while True:
        job = await queue.get()
        try:
            job.attempts += 1
            await process(job)
        finally:
            queue.task_done()
Что делает каждая строка
import asyncioПодключаем примитивы конкурентного выполнения.
from dataclasses import dataclassОписываем job коротким классом данных.
class Job:Фиксируем поля задачи, а не передаём безымянный словарь.
attempts: int = 0Считаем попытки обработки для retry policy.
queue = asyncio.Queue()Создаём очередь, безопасную для async producer и worker.
async def worker()Объявляем бесконечный цикл потребителя.
job = await queue.get()Ждём задачу, не блокируя event loop активным ожиданием.
job.attempts += 1Фиксируем очередную попытку перед обработкой.
await process(job)Вызываем долгую работу асинхронно.
queue.task_done()Сообщаем очереди, что полученная задача обработана или упала.

В реальном worker блок except должен обновлять статус и решать, поставить ли job обратно или отправить в dead-letter.

Домашняя работа: Добавить retryРеализуйте максимум три попытки, статус failed и тест на исключение process.
  • task_done вызывается всегда.
  • Попытки считаются.
  • Ошибка не убивает worker.
  • Статус доступен клиенту.

Уровень выше: Добавьте экспоненциальную задержку и jitter.

Graceful shutdown и финальные тесты · 160 минут

Сервис должен завершаться после обработки уже принятых задач, но не принимать новые. queue.join() помогает дождаться всех вызовов task_done.

async def run_demo() -> None:
    task = asyncio.create_task(worker())
    await queue.put(Job(1, "report"))
    await queue.join()
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        pass
Что делает каждая строка
async def run_demo()Описываем сценарий запуска и аккуратного завершения.
create_task(worker())Запускаем worker параллельно с producer.
await queue.put(...) Кладём конкретную задачу в очередь.
await queue.join()Ждём, пока worker отметит все задачи как завершённые.
task.cancel()Просим бесконечный worker остановиться после пустой очереди.
await taskДожидаемся завершения задачи, чтобы не оставить фоновой ошибки.
except asyncio.CancelledErrorСпокойно обрабатываем ожидаемую отмену.

Финальная проверка: задача выполняется, ошибка не теряется, повтор работает, shutdown не оставляет незакрытых задач. После этого можно заменить локальную очередь Redis/Celery.

Домашняя работа: Финальный job serviceДобавьте FastAPI endpoint POST /jobs и GET /jobs/{id}, а также README с командами запуска.
  • HTTP быстро отвечает.
  • Worker запускается отдельно.
  • Graceful shutdown проверен.
  • Есть тесты статусов.

Уровень выше: Добавьте Redis как внешний broker и метрики queue depth.
